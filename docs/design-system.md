# 設計規範

> 視覺對照頁（色票、字級、元件標本在淺色深色並排呈現）：
> https://claude.ai/code/artifact/9df0f69b-dc39-4fc6-928f-e62be58ef97f
> 那頁是輔助閱讀用的，**這份 markdown 才是正式規範**。

這份文件是**規範**，不是建議。每一條盡量寫成可以被檢查的形式，能自動檢查的都由
[`scripts/design-audit.mjs`](../scripts/design-audit.mjs) 在真實瀏覽器裡驗證，淺色與深色都要過。

改動 UI 時的優先順序：**使用者說的話 > 這份文件 > 個人品味**。
覺得某條規則擋路，就改這份文件並說明理由，不要繞過它。

## 1. 設計前提

所有規則都從這五個現場條件推導出來。看到不合理的規則，先回來看是不是漏了某個前提。

| 前提 | 對設計的意義 |
| --- | --- |
| **單手、站著、人潮在動** | 觸控目標要大、主要動作在拇指可及範圍、位置不能跳動 |
| **戶外、可能逆光** | 對比不能將就；狀態不能只靠顏色 |
| **訊號差或沒訊號** | 不得有任何操作要等網路才給回應；離線狀態必須一直看得見 |
| **使用者是志工，不是員工** | 零學習成本，不能有需要訓練才會用的互動 |
| **一次性、不能重來** | 每個可逆動作都要能復原；不可逆動作要明確確認 |

---

## 2. 設計原則

1. **未到優先。** 畫面上最大的數字永遠是「還有幾位沒到」。已到的人視覺上要退到背景。
2. **本地優先。** 任何操作都在 100ms 內從本地狀態給出結果，不等網路。網路狀態另外顯示，不阻擋操作。
3. **可逆優先。** 每一次狀態變更都提供 5 秒的無條件復原。誤觸的代價是有人被留在原地。
4. **位置穩定。** 動作按鈕不隨狀態改變位置或順序。在壓力下操作的人靠肌肉記憶，不靠閱讀。
5. **誠實。** 不確定就說不確定。離線就說離線，不要假裝已同步。

## 3. 色彩

色彩分四層，**不得跨層借用**。這是為了讓「未到（點名狀態）」和「離線（系統回饋）」即使色相接近，也能各自演進。

### 3.1 表面與文字

| Token | 淺色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--paper` | `#f5f7f8` | `#0d1315` | 頁面底色 |
| `--surface` | `#ffffff` | `#151e21` | 卡片、列、輸入框 |
| `--surface-2` | `#eceff1` | `#1d282b` | 內嵌區塊、分段控制底 |
| `--surface-3` | `#dfe4e6` | `#263336` | 進度條底、更深的內嵌 |
| `--ink` | `#10171a` | `#e9eef0` | 主要文字 |
| `--ink-2` | `#4a5a5e` | `#a4b3b6` | 次要文字 |
| `--ink-3` | `#5f6f73` | `#8b9b9f` | 輔助文字、時間、計數 |
| `--rule` | `#d7dee0` | `#29373a` | 分隔線、預設邊框 |
| `--rule-strong` | `#b5c0c3` | `#3b4b4f` | 輸入框邊框、未勾選的圈 |

`--ink-3` 是**最淺的可用文字色**。任何比它更淺的顏色都不得用於文字。

### 3.2 品牌與互動

| Token | 淺色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--accent` | `#0e5e63` | `#3fbfc7` | 主要按鈕底、選取邊框、**淺色底上的強調文字** |
| `--accent-ink` | `#ffffff` | `#06232a` | 疊在 `--accent` 上的文字 |
| `--accent-soft` | `#e2f0f0` | `#11292c` | 強調用的淡底（chip、提示框） |
| `--accent-strong` | `#0c8a93` | `#5fd8df` | 焦點框、載入指示。**不得用於一般文字** |

> `--accent-strong` 在淺色模式疊在 `--accent-soft` 上只有 3.54:1。淡底上的文字一律用 `--accent`（6.41:1）。

### 3.3 點名狀態

**只能用在名單成員的狀態**，不得用於系統訊息。

| Token | 淺色 | 深色 | 狀態 |
| --- | --- | --- | --- |
| `--st-pending` | `#a84d06` | `#e0913f` | 未到 |
| `--st-arrived` | `#1c7a44` | `#55bd7c` | 已到 |
| `--st-arrived-soft` | `#e3f2e8` | `#12291d` | 已到列的底色 |
| `--st-arrived-line` | `#a9d7bc` | `#2b5c3e` | 已到列的邊框 |
| `--st-excused` | `--ink-3` | `--ink-3` | 請假（刻意用中性色，它不是待辦） |

### 3.4 系統回饋

**只能用在系統訊息**（連線狀態、錯誤、警告），不得用於名單狀態。

| Token | 淺色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--fb-warn` | `#a84d06` | `#e0913f` | 離線、需要注意 |
| `--fb-warn-soft` | `#fbecdd` | `#2a2013` | 警告提示框底 |
| `--fb-error` | `#a02b22` | `#e5736a` | 錯誤、破壞性動作 |
| `--fb-error-soft` | `#f9e6e4` | `#2e1a18` | 錯誤提示框底 |

### 3.5 Toast

Toast 是**獨立表面，不參與明暗反轉**。舊版讓它反色（淺色模式用深底、深色模式用淺底），
結果深色模式的「復原」按鈕只有 **1.45:1**——誤觸的安全網幾乎看不見。

| Token | 淺色 | 深色 | 對比 |
| --- | --- | --- | --- |
| `--toast-bg` | `#10171a` | `#1d282b` | — |
| `--toast-ink` | `#f5f7f8` | `#e9eef0` | 16.4:1 / 12.9:1 |
| `--toast-action` | `#5fd8df` | `#5fd8df` | 10.7:1 / 8.9:1 |

### 3.6 對比要求

| 內容 | 最低比例 |
| --- | --- |
| 一般文字（< 18.66px 粗體 / < 24px） | **4.5:1** |
| 大字（≥ 24px，或 ≥ 18.66px 且粗體） | **3:1** |
| 圖示、邊框等非文字資訊 | **3:1** |

淺色與深色**都要通過**。由 `design-audit.mjs` 自動檢查。

## 4. 字級

八階，不得新增。所有字級都是 `px`，不用 `rem`——這是應用程式不是文件，不需要跟隨瀏覽器字級縮放後重排。

| Token | 值 | 用途 |
| --- | --- | --- |
| `--fs-1` | 11px | 等寬微標籤（房號、`localStorage` 之類）。**唯一允許小於 13px 的用途** |
| `--fs-2` | 13px | 說明文字、時間、計數 |
| `--fs-3` | 15px | 內文、次要按鈕、選單項 |
| `--fs-4` | 17px | 成員姓名、主要按鈕、**所有輸入框** |
| `--fs-5` | 20px | 面板標題 |
| `--fs-6` | 26px | 畫面標題 |
| `--fs-7` | 34px | 房號大字 |
| `--fs-8` | 44px | 未到人數（每個畫面最多一個） |

**輸入框一律 `--fs-4`（17px）。** iOS Safari 對小於 16px 的輸入框會自動放大頁面。

---

## 5. 間距、圓角、陰影、動態

**間距**以 4px 為基準，七階：`--sp-1` 4 / `--sp-2` 8 / `--sp-3` 12 / `--sp-4` 16 / `--sp-5` 24 / `--sp-6` 32 / `--sp-7` 48。
不得出現不在階上的值（`1px` 邊框與 `2px` 線條除外）。

**圓角**四階：`--r-1` 8px（chip、小按鈕）／ `--r-2` 12px（按鈕、輸入、列）／ `--r-3` 18px（卡片、面板）／ `--r-full` 999px（藥丸、進度條）。

**陰影**三階：`--el-1` 卡片與浮起的分段 ／ `--el-2` 底部動作列 ／ `--el-3` 面板與 Toast。不得自訂陰影。

**動態**兩階：`--dur-1` 120ms（按壓回饋）／ `--dur-2` 200ms（面板、Toast 進場），一律 `--ease: cubic-bezier(.2,.8,.3,1)`。
全部動態都必須被 `@media (prefers-reduced-motion: reduce)` 關閉。

---

## 6. 觸控與版面

| 規則 | 值 |
| --- | --- |
| 所有可互動元素的最小尺寸 | **48 × 48px** |
| 名單列（點名主要目標） | **高 ≥ 64px** |
| 底部主要動作按鈕 | **高 56px** |
| 相鄰觸控目標的間距 | **≥ 8px** |
| 內容最大寬度 | 640px，置中 |
| 頁面左右內距 | `--sp-4`（16px） |

**拇指區規則**：破壞性動作（刪除房間、換掉名單）**不得**出現在底部動作列，必須放在面板內並經過確認。

**安全區**：頂欄要加 `env(safe-area-inset-top)`，底部動作列與面板要加 `env(safe-area-inset-bottom)`。

**橫向捲動**：頁面本身永遠不得橫向捲動。內容過寬時由自己的容器 `overflow-x: auto`。

## 7. 元件規範

### 7.1 按鈕

| 變體 | 用途 | 規則 |
| --- | --- | --- |
| `btn-primary` | 每個畫面**至多一個** | `--accent` 底、`--accent-ink` 字 |
| `btn`（預設） | 次要動作 | `--surface` 底、`--rule-strong` 邊框 |
| `btn-danger` | 破壞性動作 | `--fb-error` 字，只能出現在面板內 |
| `btn-ghost` | 低權重動作 | 無邊框 |
| `icon-btn` | 純圖示 | **必須有 `aria-label`**；48×48 |

按壓回饋一律 `transform: scale(.98)`，`--dur-1`。

### 7.2 名單列

三種狀態，**顏色與形狀都要不同**（逆光下顏色會失真，色盲者看不出色相）：

| 狀態 | 底色 | 圈 | 文字 |
| --- | --- | --- | --- |
| 未到 | `--surface` | 空心圓，`--rule-strong` 邊 | 正常 |
| 已到 | `--st-arrived-soft` | **實心圓 + 勾**，`--st-arrived` | 正常，附時間 |
| 請假 | `--surface`，整列 62% 不透明 | **虛線圓** | 刪除線 |

- 整列可點，切換未到 ⇄ 已到。
- 右側固定兩個 48px 目標：撥號（僅未到且有電話時）與更多。
- `aria-pressed` 反映是否已到；`aria-label` 要說明「點下去會發生什麼」，不是「現在是什麼」。

### 7.3 Chip

三種語意，**不得混用**：

| 類別 | 樣式 | 內容 |
| --- | --- | --- |
| `chip-count` | `--accent-soft` 底、`--accent` 字 | 攜伴人數 `＋2` |
| `chip-note` | `--surface-2` 底、`--ink-2` 字 | 名單上的備註 |
| `chip-data` | `--surface-2` 底、等寬 | 電話等資料 |

點名狀態**不用 chip**，用列本身的樣式表達（見 7.2）。

### 7.4 分段控制

- 每段最小高 48px。
- 段數可能是 3 或 4（有人請假時才出現第四段），容器必須可橫向捲動且不換行。
- 選取態用 `aria-pressed`，不是 class。
- 計數用 `--ink-3`；選取那段的計數用 `--accent`。

### 7.5 面板（Sheet）

- 由底部升起，最大高 88vh，內容可捲動。
- **必須**：`role="dialog"`、`aria-modal="true"`、`aria-label`。
- **必須**：Esc 關閉、Tab 在面板內循環、關閉後焦點還原到觸發元素、點背景關閉。
- 開啟時鎖住頁面捲動。

### 7.6 Toast

- 出現在底部動作列**上方**，不遮擋它。
- `role="status"`、`aria-live="polite"`。
- 有動作時，動作按鈕最小高 44px（在 Toast 這種暫時性表面上放寬到 44）。
- 預設 5 秒後消失。**帶「復原」的 Toast 是安全機制，樣式不得低調化。**

### 7.7 同步指示

四種狀態，各有專屬顏色與文字，永遠顯示在頂欄：

| 狀態 | 顏色 | 文字 |
| --- | --- | --- |
| `online` | `--st-arrived` | 已同步 |
| `syncing` | `--accent` | N 筆待上傳 |
| `offline` | `--fb-warn` | 離線中 · N 筆待上傳 |
| `local-only` | `--ink-3` | 單機模式 |

`syncing` 的圓點可以有脈動動畫，但必須被 reduced-motion 關閉。

### 7.8 計數區

- 未到人數用 `--fs-8`，全到齊時顏色由 `--st-pending` 換成 `--st-arrived`。
- 右側顯示「已到人頭 / 總人頭」——遊覽車上要對的是人頭數不是列數。
- 進度條占滿寬度，`--st-arrived` 填色。
- 計數區捲出畫面時，頂欄要顯示精簡版計數。**這個數字不能消失。**

## 8. 互動規範

1. **不得阻塞。** 任何操作在 100ms 內給出視覺結果。網路請求一律非同步，逾時 12 秒。
2. **可逆。** 每次狀態變更後顯示帶「復原」的 Toast，維持 5 秒。
3. **不可逆的要確認。** 刪除房間、換掉名單必須經過明確確認，且說明會失去什麼。
4. **不要無聲失敗。** 任何失敗都要有可見訊息。靜默略過只允許在「失敗不影響使用者當下要做的事」時（例如常用名單載入失敗）。
5. **重複操作是安全的。** 同一個動作按兩次的結果必須跟按一次相同。

---

## 9. 無障礙

- 所有可互動元素都要有無障礙名稱（文字內容、`aria-label` 或關聯的 `<label>`）。
- 用語意元素：可點的東西是 `<button>` 或 `<a>`，不是 `<div>`。
- 焦點必須可見：`3px solid var(--accent-strong)`，`outline-offset: 2px`。
- 切換態用 `aria-pressed`，展開態用 `aria-expanded`，進度用 `role="progressbar"` 加 `aria-valuenow`。
- 動態內容用 `aria-live`：Toast 用 `polite`。
- 尊重 `prefers-reduced-motion` 與 `prefers-color-scheme`。

---

## 10. 文案

- **說會發生什麼，不說系統怎麼運作。** 寫「還有 4 位沒到」，不是「pending: 4」。
- **錯誤訊息要包含「怎麼辦」。** 「目前連不上網路。你可以繼續點名，恢復連線後會自動上傳。」
- **不要道歉，不要含糊。**
- **按鈕寫動詞**，而且要跟結果一致：按「複製結果」之後 Toast 說「結果已複製」。
- **所有使用者可見字串都放在 `src/lib/i18n.ts`。** `zh` 是來源，`en` 由型別強制必須有相同的鍵。元件裡不得寫死中文。

## 11. 每個畫面都要定義的四種狀態

| 狀態 | 要求 |
| --- | --- |
| 載入中 | 有明確的載入訊息，不是空白畫面 |
| 空 | 說明為什麼空、以及可以做什麼 |
| 錯誤 | 說明發生什麼、以及下一步（通常是重試或返回） |
| 離線 | 可用的部分照常運作，不可用的部分明確標示 |

「未到」篩選下的空狀態是特例：那是**成功**，要寫「太好了，全部都到了」而不是「沒有資料」。

## 12. 自動檢查

`node scripts/design-audit.mjs` 在真實瀏覽器裡走過主要畫面，淺色深色各驗一次：

| 檢查 | 對應章節 |
| --- | --- |
| 文字對比 ≥ 4.5:1（大字 3:1） | 3.6 |
| 可互動元素 ≥ 48×48（Toast 動作 ≥ 44） | 6 |
| 字級都在八階白名單內 | 4 |
| 所有可互動元素都有無障礙名稱 | 9 |
| 頁面沒有橫向捲動 | 6 |
| 每個畫面至多一個 `btn-primary` | 7.1 |

沒過就是規範被違反了，修程式碼或修規範，二選一。
