# 設計評估報告 · 2026-09 · 形狀與類型

> [2026-08](design-review-2026-08.md)：63 條可行動的問題。
> [2026-09 整體性](design-review-2026-09.md)：問題之間的關係。
> [2026-09 配色](design-review-2026-09-color.md)：顏色。
> **這一份：形狀與類型。**

配色重構結束之後把六個畫面再並排看一次，剩下的違和感全部不在顏色上。
一顆按鈕、一個人、一則錯誤訊息、一張 QR 卡片、一條 Toast——**它們是同一個形狀**。

而這件事其實早就被記錄過。整體性評估的 §1.2 標題就叫「所有東西都是同一種盒子」，
內文寫著：

> 規範裡其實已經有三次針對「框中框」「一疊盒子」的修正紀錄——但每一次都只拆掉當時
> 那一個框。**沒有一條規則說「什麼東西該有框，什麼東西不該有」。**

那份報告找到了洞，然後**沒有人把那條規則寫下來**。這一份補的就是它。

## 1. 診斷：把全站的形狀抽出來數一次

把 `styles.css` 去掉註解、逐條規則拆開，只看 `border-radius`：

| 圓角 | 條數 | 誰 |
| --- | --- | --- |
| `--r-2` 12px | **20** | 按鈕、圖示鍵、輸入框、代碼框、空間列、分段軌道、名單列、結果預覽、骨架、選單列、複製框、代碼大字、連結、QR、解析預覽、提示框、橫幅、Toast⋯ |
| `--r-1` 8px | 5 | 對焦框、分段內段、清除鍵、chip、Toast 的復原鍵 |
| `--r-full` | 4 | 身分圖示、分組晶片、辨識晶片、面板握把 |
| `--r-3` 18px | 2 | 掃碼取景框、對話框 |
| `50%` | 2 | 同步圓點、勾選圈 |

**38 條形狀規則裡有 20 條是同一個值。**

### 1.1 `--r-2` 是預設值，所以它什麼都沒說

一個值用在超過一半的元件上，它就不再是一個選擇，而是「沒有選」。
於是形狀完全不參與溝通：看一眼分不出哪個是可以按的、哪個是只能讀的、
哪個是裝東西的容器。

### 1.2 `--r-3` 的規範描述了一個不存在的用法

`03-tokens.md` 寫著 `--r-3` ＝「卡片、面板、對話框」。
但實作裡的**卡片**——`.recent-item`（首頁的空間列）、`.member`（名單列）——
**從來都是 `--r-2`**。真正用 `--r-3` 的只有面板、對話框，和一個誤用。

規範描述了一個不存在的用法整整一年。後果是可預測的：任何人想做「比較大的卡片」
就會伸手拿 `--r-3`，而那正是掃碼取景框發生的事——一個嵌在面板裡的取景器，
用了跟面板本身一樣的圓角，讀起來像面板裡又疊了一張面板。

### 1.3 規範只訂了兩種表面，實作有三種，而第三種沒有名字

整體性評估訂下的表面規則是兩條：

| 角色 | 用什麼 |
| --- | --- |
| 卡片／列／覆蓋層 | `--surface` ＋ 邊框 ＋ **陰影** |
| 凹槽 | `--surface-2`，不加邊框 |

但實作裡有**第三種**在大量使用：`--surface` ＋ `--rule` ＋ **沒有陰影**。
`.preview`、`.copy-row`、`.qr-card`、`.code-display`、`.link-display`、
`.skeleton-row` 全都是它。

**沒有名字的東西沒有規則，沒有規則就沒有邊界。** 於是「可以按的列」與
「只能讀的內容」用同一組底、邊、圓角，差別只剩一層幾乎看不見的陰影，
而那層陰影是誰有誰沒有，是隨機的。

### 1.4 陰影的意思已經被指派了，只是沒有人知道

配色重構那一輪最好的一個決定是名單列的狀態：**未到浮起（還要你動手）、
已到沉回頁面（不用了）**。那條規則在 `.member` 上成立，而且在明暗兩個主題都成立。

但它只做進了一個元件。同一個機制在其他二十個元件上沒有被套用，
於是「浮起來」這個訊號在這個 app 裡**同時有意義又沒有意義**。

### 1.5 對焦時元件會變形狀

```css
:focus-visible { outline: …; border-radius: var(--r-1); }
```

這一行不是在畫對焦框的圓角——`border-radius` 是設在**元件自己**身上的。
有自己圓角的元件（`.btn` 12px、`.group-chip` 999px）因為宣告在後面而僥倖沒事；
**沒有自己圓角的就真的變了**。實測用 Tab 走一遍：

| 元件 | 平常 | 被 Tab 到 |
| --- | --- | --- |
| `.member-main` | 0px | **8px** |
| `.topbar-title` | 0px | **8px** |

`.member-main` 是貼齊 12px 圓角父層的滿版列。它被聚焦時長出一個 8px 的圓角，
於是那圈框跟它框住的東西對不上——**一個只有鍵盤使用者看得到的形狀 bug**。

### 1.6 有兩組東西是「同一種東西的兩個版本」

| | | |
| --- | --- | --- |
| `.select-row` | 設定面板的一列 | `min-height: 48` |
| `.menu-item` | 「更多」面板的一列 | `min-height: 56` |

兩個都是「面板裡的一列，點了會怎樣」。同一個 app 的兩張面板，兩個列高。

| | | |
| --- | --- | --- |
| `.icon-btn` | 48px 圖示鍵 | `--r-2` |
| `.search-clear` | 48px 圖示鍵 | `--r-1` |

同一種按鈕，兩個圓角，差別只在它剛好長在哪一個容器裡。
`.toast-action` 同理：全 app 唯一一顆形狀跟其他按鈕不一樣的按鈕，
偏偏是最重要的那一顆（唯一的復原機會）。

### 1.7 三處「看起來是系統，其實不是」

- **`.chip-count` 與 `.chip-note` 是空的。** 它們各自把 `.chip` 已經給過的
  底色與文字色**一字不差再寫一次**，沒有加任何東西。CSS 看起來有四種晶片，
  實際上只有兩種長相。
- **`.code-display` 與 `.link-display` 的底、邊、圓角是死程式碼。** 它們只在
  `.copy-row` 裡出現，而 `.copy-row > .code-display` 把那三個屬性全部覆寫掉。
  三行永遠不會被畫出來的宣告，讀 CSS 的人卻會以為它是一個有框的元件。
- **`.banner` 這個類型已經不存在了。** 它最後剩兩個變體，而兩個都不想當橫幅：
  `.banner-result` 是一張卡片，`.banner-muted` 把它給的底色與內距全部覆寫成
  透明與 0，只留下 flex 與下邊距。

## 2. 規則：兩條互不干涉的軸

寫進 [04 元件 · 表面與形狀](design/04-components/README.md)，那是規範，不是這份報告。

> **表面說「這是什麼種類」，圓角說「這東西多大、包在誰裡面」。**

把語意塞進圓角、或把尺寸塞進表面，就是 §1 那些混亂的來源。

### 2.1 軸一 · 表面 ＝ 種類

照順序問，第一個答「是」的就是它的類型。一個元件只能屬於一種。

| 它是⋯ | 簽名 |
| --- | --- |
| **控制項**——你直接操作它 | `--surface` ＋ `--rule-strong`，不浮 |
| **可按的內容塊**——整塊按進去 | `--surface` ＋ `--rule` ＋ `--el-1`，**浮起** |
| **靜態內容塊**——只能讀 | `--surface` ＋ `--rule`，**平的** |
| **凹槽**——裝別的東西 | `--surface-2`，不描邊、不浮 |
| **覆蓋層**——浮在遮罩上 | `--surface` ＋ `--el-3` |
| **嵌在上面某一塊裡的觸控區** | 透明，只有 hover／active 才有底 |

**一句話：陰影的意思是「這一整塊可以按」。**
這不是新發明的，是 §1.4 那條本來就在名單列上的規則，現在推廣到全站。

### 2.2 軸二 · 圓角 ＝ 尺寸與巢狀

| Token | 判準 |
| --- | --- |
| `--r-full` | **高度就是它的直徑** |
| `--r-3` | **只有覆蓋層**。它不是「比較大的卡片」 |
| `--r-2` | 頁面流裡的一切。**它是預設值，所以它不表示任何事** |
| `--r-1` | **內圓角 ＝ 外圓角 − 內距**。分段控制：12 − 4 = 8 |
| `50%` | 真正的圓 |

唯一一個圓角帶語意的地方是**藥丸**（「屬於哪一群」）。它成立是因為藥丸的形狀
來自高度，不是來自重要性——所以它沒有違反這條軸。

## 3. 改了什麼

| 改動 | 對應 |
| --- | --- |
| `:focus-visible` 不再設 `border-radius`；把圓角還給 `.member-main` 與 `.topbar-title` | §1.5 |
| 掃碼取景框 `--r-3` → `--r-2`，並拿掉那圈邊（它是凹槽） | §1.2、§1.3 |
| `.search-clear` `--r-1` → `--r-2`（圖示鍵一律 `--r-2`） | §1.6 |
| `.toast-action` `--r-1` → `--r-2`（它是按鈕） | §1.6 |
| `.select-row` 48 → `--tap-lg`（56），跟 `.menu-item` 同高 | §1.6 |
| `.chip-count` 與 `.chip-note` 的重複宣告刪除 | §1.7 |
| `.code-display` 與 `.link-display` 的死表面宣告刪除 | §1.7 |
| `.banner` 整個類型移除 → `.result-card` ＋ `.page-note` | §1.7 |
| `.result-card` 拿掉 `--el-1`（靜態內容塊不浮） | §1.4 |

最後一條值得單獨記一筆：**那層陰影是上一輪配色重構自己加的。**
把結果橫幅從警告色改成卡片時順手加了 `--el-1`，因為當時「卡片」的定義就含陰影
——而那時候還沒有「陰影＝可以按」這條規則。**規則寫下來之後，第一個被它抓到的
是規則作者自己上一輪的改動。**

### 3.1 改完之後的形狀分佈

| 圓角 | 前 | 後 | |
| --- | --- | --- | --- |
| `--r-3` | 2 | **1**（＋`.sheet` 的上兩角） | 只剩 `.dialog` 與 `.sheet`：**只有覆蓋層** |
| `--r-1` | 5 | **2** | 只剩 `.segment`（內圓角）與 `.chip`（嵌在列裡） |
| `--r-2` | 20 | 23 | 更多了，而這是對的：它現在明確是「沒有特別形狀」的預設值 |

`--r-2` 變多不是退步。**把假的差異收掉之後，剩下的差異才是真的差異**——
現在畫面上出現非 `--r-2` 的圓角，都在說一件具體的事（這是藥丸／這是覆蓋層／
這嵌在別的東西裡）。

## 4. 這四條有測試在擋

規範沒有測試就會漂移，這件事這個專案已經證明過三次（§1.2 的 `--r-3`、
整體性評估 §1.4 的三處散文漂移、配色重構 §2.6 的死程式碼）。
所以這一輪的四條規則直接寫成 `src/styles.test.ts` 的檢查：

| 檢查 | 擋什麼 |
| --- | --- |
| `--r-3` 只給覆蓋層 | 允許清單只有 `.sheet` 與 `.dialog` |
| `--el-1` 只給「整塊可以按」的東西 | 允許清單只有 `.recent-item`、`.member`、分段控制選中的那一格 |
| 凹槽不描邊 | `--surface-2` 底不得同時有 `--rule` 邊框 |
| 狀態選擇器不得改元件形狀 | `:focus`／`:hover`／`:active` 裡不得有 `border-radius` |

**四條都實測過會擋。** 逐一注入一個違規（給 `.qr-card` 加 `--r-3`、給 `.preview`
加 `--el-1`、給 `.note` 加邊框、給 `.icon-btn:hover` 加圓角），四個檢查各自
紅一次，再還原。**一個只會通過的檢查比沒有檢查更糟**，因為它會讓人以為那條規則
有人在守。

## 5. 這一輪學到的

### 5.1 找到洞不等於補上洞

整體性評估寫下「沒有一條規則說什麼東西該有框」，然後修掉了當時看到的那幾個框，
就結束了。**一個月後，`--r-2` 從 18 條長到 20 條。**

找到系統性問題的報告，如果只修了症狀，下一輪會在同一個地方再找到它一次。
**報告的產出應該是一條規則，不是一串修好的元件。**

### 5.2 沒有名字的東西沒有規則

第三種表面（`--surface` ＋ `--rule` ＋ 無陰影）被六個元件使用了很久，
而規範裡連提都沒提過它。它不是被違反，是**根本不在規則的定義域裡**。

看到實作裡有一種反覆出現的做法而規範沒有描述它，那不是實作在偷跑，
是規範漏了一格。

### 5.3 預設值不能拿來表達任何事

`--r-2` 佔一半以上，所以「用 `--r-2`」不是一個決定。想靠它說「這比較重要」
或「這是另一種東西」，讀的人收不到。**要說種類就換表面，要說層級就換位置、
字級或顏色。**

### 5.4 狀態不得改形狀

`:focus-visible` 裡的 `border-radius` 看起來像是在設定對焦框，實際上是在改元件。
這類 bug 的特徵是**只有一部分使用者看得到**（這裡是鍵盤使用者），
所以它可以躺很久。

一般化：**寫在狀態選擇器裡的幾何屬性都要停下來問一次**——這是在描述狀態的樣子，
還是在改元件本身？

### 5.5 「為了語意」不是重複宣告的理由

`.chip-count` 與 `.chip-note` 各自把父類的樣式再寫一次，讓 CSS 看起來有四種晶片。
**名字是給 markup 讀語意用的，不是給它長得不一樣用的。** 想保留語意名稱就保留，
但不要為了「看起來成套」而複製宣告——那會讓下一個人以為這裡有四種選擇。

### 5.6 變體不得把繼承來的東西整組退掉

`.banner-muted` 把 `.banner` 給的底色與內距全部覆寫成透明與 0。
那不是一個變體，那是一個借了名字的陌生人。

**判準：如果一個變體把父類給的東西大部分退掉，它就該獨立。**
（`.banner` 因此整個移除，兩邊各自拆成完整的東西。）
