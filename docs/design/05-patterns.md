# 05 · 模式

元件是零件，模式是把零件組起來的規則。

---

## 5.1 版面

| 規則 | 值 |
| --- | --- |
| 內容最大寬度 | 640px，置中（`.shell`） |
| 頁面左右內距 | `--sp-4`（16px） |
| 名單下方內距 | 160px，讓開右下角的浮動搜尋鍵與點名後彈出的 Toast |
| 斷點 | 700px + 橫向（平板兩欄）、640px（看板的分組列換行）、359px（極窄手機） |
| 橫向捲動 | **頁面本身永遠不得橫向捲動。** 內容過寬時由自己的容器 `overflow-x: auto` |

**主要介面是單欄。** 三個斷點各有具體理由，不是為了「支援平板」而支援：

- `@media (min-width: 700px) and (orientation: landscape)` — 名單排成兩欄
  （`grid-template-columns: repeat(auto-fill, minmax(300px, 1fr))`），`.shell`
  放寬到 900px。看板模式才是平板的正式定位，但 `#/r/<代碼>` 在平板上完全可達
  ——掃 QR 進來的就是這個畫面，而教會團體最常有的閒置裝置正好是平板。
  1024×768 橫放時原本只看得到 3 個人（比手機還少），左右各空 208px。
  grid 是列優先流動，所以 `sort_order` 的閱讀順序不變；分組標題要
  `grid-column: 1 / -1` 橫跨整列。
- `@media (max-width: 640px)` — 看板的分組列與「離開看板」各佔一行。
- `@media (max-width: 359px)` — 極窄手機上把非必要的按鈕文字收起來。

**安全區**：頂欄加 `env(safe-area-inset-top)`；浮動搜尋鍵、開空間的底部動作列與面板都加 `env(safe-area-inset-bottom)`。

**拇指區**：主要動作在畫面下半部。**破壞性動作不得出現在底部動作列或浮動鍵**，必須在面板內並經確認。

## 5.2 導覽

三個畫面，hash 路由（GitHub Pages 對未知路徑回 404、沒有 SPA fallback）。

| 路徑 | 畫面 | 返回去哪 |
| --- | --- | --- |
| `#/` | 首頁 | — |
| `#/new` | 開啟空間 | 首頁 |
| `#/r/<代碼>` | 空間 | 首頁 |
| `#/b/<代碼>` | 看板模式 | 空間 |
| `#/j/<代碼>` | 加入連結 | 立刻 `replace` 成 `#/r/<代碼>` |

**加入連結用 `replace` 不用 `push`**：重新整理或按上一頁時不該又跑一次加入流程。

返回鍵一律回首頁，不做歷史堆疊——這個產品只有三層深，堆疊只會讓人迷路。

## 5.3 每個畫面都要定義的四種狀態

| 狀態 | 要求 |
| --- | --- |
| **載入中** | 有明確的載入表示，不是空白畫面。超過 300ms 才顯示 |
| **空** | 說明為什麼空、以及可以做什麼 |
| **錯誤** | 說明發生什麼、以及下一步（通常是重試或返回） |
| **離線** | 可用的部分照常運作，不可用的部分明確標示 |

「未到」篩選下的空狀態是特例：那是**成功**（見 [元件 · 回饋](04-components/feedback.md)）。

## 5.4 離線降級語言

離線不是錯誤，是預期狀態。畫面該長這樣：

| 功能 | 離線時 |
| --- | --- |
| 點名（切換狀態） | **照常運作**，寫入本地並排入待送佇列 |
| 臨時加人 | **照常運作**，用前端產生的 id，重送冪等 |
| 搜尋、篩選、匯出、列印 | **照常運作**（全部讀本地狀態） |
| 進入已快取的空間 | **照常運作** |
| 進入沒快取過的空間 | 失敗，顯示錯誤與返回鍵 |
| 改名單、再開一個、關閉／刪除 | 失敗，顯示「目前連不上網路」 |

**規則**

- 同步指示一直顯示，並帶待上傳筆數。
- **不得快取 API 回應。** 寧可顯示離線，也不要拿舊快照騙人說已經同步。
- 恢復連線後自動送出，不需要使用者動作，也不跳提示（那是預期行為，不是事件）。

## 5.5 破壞性動作的三段式

| 段 | 做什麼 | 例子 |
| --- | --- | --- |
| 1. 事前 | 在動作旁邊寫清楚後果 | 選單項副標「同一份名單、狀態全部歸零」 |
| 2. 當下 | 確認對話框，說明**會失去什麼**，初始焦點在取消 | 「刪除後無法復原，所有點名紀錄都會消失。」 |
| 3. 事後 | 可逆的給 5 秒復原；不可逆的不給假希望 | 點名 → Toast 復原；刪除空間 → 沒有復原 |

**判斷用哪一種：**

- 能用一次反向操作還原 → 只要 Toast 復原，**不要**確認對話框
- 不能還原 → 確認對話框
- 兩者都給 = 確認疲勞，下一個確認就少被讀一次

## 5.5.1 衝突提示

LWW 讓合併有明確勝負，但**靜默覆蓋很危險**：我把王小明標成已到、別人同時標成未到而且贏了，如果我完全不知道，就會以為他已經上車。

規則：

- 只在**我近期改過**（90 秒內）的成員被較新的變更覆蓋時提示。別人改別人的不打擾我。
- 提示內容要說是誰改的：「王小明 已由陳姐改為未到」。對方沒填名字時退回「已被其他人改為…」。
- 一次多筆時合併成「有 N 筆點名被其他人改過」，不要連續彈五個。
- 提示不帶「復原」——要改回去請自己點，否則兩台裝置會互相覆蓋沒完沒了。
- 顯示 7 秒（比一般 Toast 長，因為它需要被讀懂而不只是被看到）。

三條同步路徑都要檢查：Realtime 廣播、定期對帳、以及送出成功後伺服器回填的值。

## 5.5.2 帳號

**只有主揪需要帳號。協助點名的人永遠不用。** 掃 QR 就能點是這個產品的生命線——一旦要求五個同工在遊覽車門口註冊，整個東西就廢了。

**登入方式：Google 為主，Email 六碼驗證碼為備援。**

| | 為什麼 |
| --- | --- |
| Google（主要） | 一次點擊，不必離開 App 去收信；不吃 Supabase 的寄信額度（免費方案每小時只有個位數封）；也不必請每個部署者去改信件模板 |
| Email 六碼（備援） | **Google 在 App 的內建瀏覽器裡會直接擋掉 OAuth**（`disallowed_useragent`），而主揪很可能就是從 LINE 群裡點自己的分享連結進來的。沒有備援的話那是一條死路。另外也不是每個人都有、或都想用 Google 帳號 |

**規則**

- **用 PKCE，不用 implicit flow。** implicit 會把 token 放在網址的 hash 裡回來
  （`#access_token=…`），而這個 App 用的就是 hash 路由——路由器會把一串 token
  當成路徑。PKCE 走 `?code=`，跟 hash 沒有交集；順帶讓 token 從不出現在網址列
  與瀏覽紀錄裡。
- **回呼的 code 一定要從網址上清掉**（`history.replaceState`）。留著的話使用者
  重新整理就會拿一個用過的 code 再換一次，然後看到一個沒頭沒尾的錯誤。
- **導走之前記下目前的路由**，回來要把人放回原處，而不是一律丟回首頁。
  存 `sessionStorage`，不塞進 `redirect_to`——GoTrue 對帶 hash 的 redirect_to
  處理方式不一。
- **成功與失敗都只能用 Toast 講，而且一定要講。** 使用者按下按鈕之後整個分頁
  就被導走了，回來時 App 是從零載入的：什麼都不說的話，他會看到一個「好像沒
  登入成功」的首頁。
- **在 Google 那一頭按取消不是錯誤**，不要當錯誤講。
- **內建瀏覽器的提示是「先說一聲」，不是「擋起來」。** 偵測靠 UA 猜，會猜錯，
  所以按鈕不停用——猜錯時最壞的結果是多顯示一句提示，而不是把一條可行的路
  擋掉。提示裡要給兩條出路：用瀏覽器開啟，或改用 Email 備援。

擁有權有兩條路，任一相符即可：

| 路徑 | 存在哪 | 什麼時候有用 |
| --- | --- | --- |
| `owner_key` | 開空間那台裝置的 IndexedDB | 從不登入的人，行為完全不變 |
| `owner_id` | 主揪登入後的帳號 | 換手機、清了快取、或想在兩台裝置間切換 |

規則：

- **不登入的路徑不得退化。** 開空間、點名、分享、匯出、列印全部不需要帳號。
- **「再開一個」刻意不在擁有權後面。** 只要拿得到代碼就能再開，新空間的擁有者
  是複製的那個人（對原空間仍然沒有任何管理權）。
  理由：複製對來源空間完全無害（一個字都不改），而名單本來就對所有拿得到代碼的
  人可見（「代碼就是密碼」），把它鎖起來沒有保護到任何東西；代價卻是三個真實
  劇本無解——主揪臨時不能來、手機在遊覽車上沒電、在山區沒訊號被降級成協助者。
  那時候「回程再點一次」是產品方向書明列的核心情境，現場卻只能重貼一次 LINE
  接龍重開空間。
  **判斷標準：一個操作若不改動來源、也不揭露呼叫者本來就看不到的東西，
  擁有權檢查就沒有在保護什麼，只是在擋人。**
- 登入是**設定面板裡的一個選項**，不是啟動時的關卡，也不是任何功能前面的擋板。
- 登入後**立刻認領**這台裝置本來就擁有的空間與名單。看到空的「我的活動」會讓人以為壞掉。
- 認領只認 `owner_key`——也就是「這台裝置本來就管得動的東西」。它不能用來認領別人的空間，因為 `owner_key` 從不外流（快照與分享連結都不含它）。
- **登出不清除 `owner_key`**，所以這台裝置仍然管得動自己開的空間。
- 「我的活動」與「最近的空間」是兩個不同的清單：前者是帳號名下的（跨裝置），後者是這台裝置去過的（含以協助者身分加入的）。**不要合併**，它們回答的是不同的問題。

## 5.6 鍵盤

雖然主要用手機，鍵盤操作必須完整可用（無障礙、以及平板接鍵盤當看板的情境）。

| 按鍵 | 行為 |
| --- | --- |
| `Tab` / `Shift+Tab` | 依視覺順序移動焦點 |
| `Enter` / `Space` | 觸發聚焦的按鈕；在名單列上＝切換狀態 |
| `Esc` | 關閉面板或對話框（等同取消） |
| `Enter`（代碼輸入） | 送出加入 |

**焦點順序**：頂欄 → 搜尋 → 篩選 → 名單（依顯示順序）→ 浮動搜尋鍵（點名畫面）／底部動作列（開空間）。

**焦點外框**：3px `--accent-strong`，`outline-offset: 2px`。**不得移除**，即使覺得不好看。

**模態層**：焦點鎖在層內，關閉後還給觸發元素，背景加 `inert`。

## 5.7 手勢

| 手勢 | 狀態 |
| --- | --- |
| 點擊 | 全部互動的唯一方式 |
| 垂直捲動 | 名單、面板內容 |
| 水平捲動 | 只有分段控制（段數多時） |
| **滑動刪除／滑動標記** | **禁止** |
| 長按 | 不使用 |
| 雙擊 | 不使用 |
| 下拉重新整理 | 不使用（有定期對帳與回到前景對帳，不需要） |

**為什麼禁止滑動手勢**：捲動找人時很容易誤觸，而在這個產品裡誤觸的代價是有人被留在原地。
`overscroll-behavior-y: none` 也是同一個理由——避免在名單頂端多滑一下觸發瀏覽器的重新整理。

## 5.8 觸覺回饋

點名成功時 12ms 短震（`navigator.vibrate`）。

**這不是裝飾**：逆光下看不清螢幕、或視線正盯著排隊的人而不是手機時，震動是「這一下有記到」的第二個確認管道。

規則：只在**狀態真的改變**時震；可在設定關閉；iOS Safari 不支援，要當作加分項而非依賴。

## 5.9 捲動與黏著

| 元素 | 行為 |
| --- | --- |
| 頂欄 | 黏在上方 |
| 底部動作列（開空間）／浮動搜尋鍵（點名） | 固定在下方 |
| 篩選與搜尋 | **住在頂欄裡**，所以跟著黏住 |
| 分組晶片 | 會捲走（黏太多東西會吃掉名單空間） |

原則：**只有「不能消失的資訊」值得黏著**。這個產品裡只有兩個：未到人數、同步狀態。兩個都在頂欄——未到人數就是篩選那排的「未到 N」。

計分區（44px 大字＋「N / M 人」＋進度條）曾經佔著首屏的頂部並且會捲走，靠
「捲出畫面時頂欄接手」補救。整塊拿掉之後那套機關也不需要了：數字本來就一直
在畫面上。

## 5.10 多裝置一致性

五個人同時看同一份名單，**看到的順序必須完全一樣**，否則「第三個那位」會指到不同的人。

- 名單排序：`sort_order` → `created_at` → `id`，三層全部指定，不依賴資料庫的預設順序。
- 篩選與搜尋是**本機狀態**，不同步——每個人可以看不同的切片。
- **「我打過這位了」不做記號。** 曾經有過（本機的 `calledAt`，撥號鍵旁邊留一個
  「已撥 15:42」），後來拿掉：它只記得**這支手機**打過誰，五個人各自催人時互相
  看不到，那個記號說的話比它知道的多。要做就得是共享狀態——多一種 `PendingOp`、
  一支 RPC 與一輪衝突處理（路徑是照 `set_member_group` 複製一支 `set_member_note`）
  ——而不是一個只對自己成立的印象。
- 點名狀態是**共享狀態**，合併規則見 `src/lib/merge.ts`。

## 5.10.1 誰在這個空間裡（presence）

06:50 車門口，「大家都進來了嗎」只能用喊的——而喊得到的前提是五個人在同一個
地方，他們散在兩台車的前後門。更常見的失敗是有人掃了 QR 但停在瀏覽器的
「要開啟嗎」對話框上，自己以為進來了；等到 07:12 發現有一車根本沒人在點，
已經沒有第二次機會。

分享面板顯示目前在空間裡的裝置與名字，沿用已存在的 `room:<code>` 頻道。

**規則**

- **presence 的 key 用裝置的 `owner_key`**：同一支手機重連時取代自己那一筆，
  不會在名單上留下幽靈。
- **`presenceReady` 是「這份名單可信」的旗標，不是「有幾個人」的替代品。**
  REST 通了不代表 Realtime 也通了（自架、代理、公司防火牆擋 WebSocket 都會
  造成這種狀態）。沒有這個旗標的話，分享面板會在別人明明已經進來時說「目前
  只有你」——那正是這個產品最不能犯的那種錯。**不知道就整區不顯示**，不要猜。
- 沒寫名字的人不逐一列出，只算支數（「陳姐、阿明，另外 2 支沒寫名字」）——
  五個「點名員」列出來沒有任何資訊量。
- 改完自己的名字要重新 `track`，否則空間裡的其他人會一直看到舊的。

## 5.11 列印

紙本備援：手機沒電時要能接手。

- 印出來的是**空白待勾名單**，不是螢幕的複製品。已點狀態不印——紙本的用途是「從頭重點一次」。
- 隱藏：頂欄（篩選與搜尋都在裡面）、浮動搜尋鍵、Toast、疊層、所有按鈕。
- **抬頭是專用的 `.print-head`，不得借用螢幕元素。** 它必須印出活動名稱、代碼、
  總人數，以及「日期／點名者／完成時間」三個空格。
  一度是把螢幕上那塊計分區借來當標題，於是紙上印的是「還有 12 位沒到」——一個
  離開印表機就過期的數字，而真正需要的活動名稱與代碼反而被 `display: none`
  掉了。拿著這張紙的人是因為手機沒電，他必須自己看得出這是哪一場。
- **兩欄，一車一欄**（`columns: 2` + `.group-divider { break-before: column }`）。
  單欄時每一列只用掉 15% 的行寬，20 個人印成 5 張 A4；而這是「手機沒電」時的
  備援，張數愈少愈可能真的被帶在身上。一車一欄還可以直接撕開分給兩個顧車的人。
- **電話要印出來。** 收尾時「看到未到 → 打電話」是唯一的下一步，而螢幕上撥號
  只做成 `tel:` 連結（列印時整個 `.member-side` 會被藏起來）。舊名單的 `phone`
  欄位走 `.print-phone`；新解析的名單號碼在備註裡，而備註本來就會印成純文字。
- 每列一個空心方框給人用筆勾，列間虛線分隔，`break-inside: avoid`。
- 強制白底黑字（螢幕的深色主題不該印出滿版黑）。所有 chip 在紙上都退成純文字。
- `@page { size: A4 portrait; margin: 12mm 10mm 14mm }`。
