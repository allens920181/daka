## 7.1 無障礙

目標：**WCAG 2.1 AA**。

| 項目 | 要求 |
| --- | --- |
| 文字對比 | 一般 ≥ 4.5:1，大字 ≥ 3:1，淺色深色都要過 |
| 非文字對比 | 圖示、邊框、狀態指示 ≥ 3:1 |
| 觸控目標 | ≥ 48 × 48px（Toast 動作 44px） |
| 無障礙名稱 | 每個可互動元素都要有 |
| 語意元素 | 可點的是 `<button>` 或 `<a>`，不是 `<div>` |
| 焦點可見 | 3px `--accent-strong`，`outline-offset: 2px`，不得移除 |
| 狀態表達 | **不得只靠顏色**。狀態要同時有形狀或文字 |
| 動態偏好 | 尊重 `prefers-reduced-motion` |
| 主題偏好 | 尊重 `prefers-color-scheme`，並提供明確覆寫 |
| 模態層 | 焦點鎖定、Esc 關閉、焦點還原、背景 `inert` |
| 即時區域 | Toast 用 `aria-live="polite"`（不用 `assertive`，那會打斷正在唸的名字） |

**ARIA 對照**

| 情境 | 屬性 |
| --- | --- |
| 切換態（名單列、分段） | `aria-pressed` |
| 面板 | `role="dialog"` + `aria-modal` + `aria-label` |
| 確認對話框 | `role="alertdialog"` + `aria-labelledby` + `aria-describedby` |
| 進度 | `role="progressbar"` + `aria-valuenow/min/max` + `aria-label` |
| 載入 | `role="status"` + `aria-busy` |
| 分段容器 | `role="group"` + `aria-label`（**不是** `tablist`） |

## 7.2 效能預算

效能在這個產品裡是設計需求，不是最佳化議題——它直接決定「早上七點在停車場打不打得開」。

| 指標 | 預算 | 現況 |
| --- | --- | --- |
| 主 bundle（gzip） | ≤ 60 KB | ~43 KB |
| 首次載入總量（gzip） | ≤ 120 KB | ~60 KB |
| 網路字型 | **0** | 0 |
| 點擊到畫面更新 | ≤ 100ms | 本地寫入，無網路往返 |
| 網路請求逾時 | 12 秒 | `AbortSignal.timeout` |
| 名單規模 | 1000 人不卡頓 | 每人一列，無虛擬捲動 |

**超出預算時的順序**：先砍相依套件，再砍功能，最後才考慮放寬預算。

已經做過的取捨：捨棄 `@supabase/supabase-js` 改用 `fetch` 直打 PostgREST（主 bundle 315 KB → 132 KB），QR 產生器改動態載入。

## 7.3 瀏覽器支援

| 瀏覽器 | 版本 | 理由 |
| --- | --- | --- |
| iOS Safari | 15.5+ | `inert` 屬性 |
| Chrome / Edge | 102+ | `inert` |
| Firefox | 112+ | `inert` |
| Android Chrome | 最近兩年 | — |

用到的較新特性與降級行為：

| 特性 | 沒有時 |
| --- | --- |
| `inert` | 背景仍可被 Tab 到（焦點陷阱仍生效，只是不完美） |
| `IntersectionObserver` | 頂欄不接手顯示計數 |
| `crypto.randomUUID` | 需要安全內容（HTTPS 或 localhost），GitHub Pages 符合 |
| `color-mix` | 未使用（刻意避開，支援度不齊） |

## 7.4 自動檢查

| 檢查 | 指令 | 驗什麼 |
| --- | --- | --- |
| Token 靜態檢查 | `npm test` | 原始碼有沒有繞過 token：硬寫色值、字級、z-index、動畫時間、間距、rgba、opacity；以及每個色彩 token 在三種主題狀態都有定義 |
| 設計規範執行期檢查 | `npm run audit:design` | 六個畫面、淺色深色各一次：文字對比（含祖先 opacity）、非文字元件對比、觸控尺寸、字級、無障礙名稱、橫向溢出、每畫面至多一個主要按鈕 |
| 元件行為 | `npm run e2e` | 焦點管理、Esc、復原、確認對話框的初始焦點、列印樣式、單機模式的誠實 |

**檢查工具本身也會有盲點，發現一個就補一個。** 已經補過的兩個：

1. **祖先的 `opacity` 讀不到。** `getComputedStyle(el).color` 給的是「宣告的
   顏色」。`.member.is-excused { opacity: .62 }` 這種寫法會把裡面 13px 的說明
   文字實際壓到 **2.5:1**，而檢查照樣說通過——螢幕上看得見的問題，工具看不見。
   現在會把祖先鏈上的 opacity 乘起來，混進背景之後再比。
   （WCAG 1.4.3 明確豁免停用中的控制項，所以 `[disabled]` 子樹不計。）
2. **沒有自己文字節點的元素整個被跳過。** 檢查以「有文字的元素」為單位，於是
   `.check`（未到的空心圈）這種「形狀就是資訊」的元素從來沒被驗過——它一度只有
   **1.86:1**。現在 `.check`、`.sync-dot`、`.chip-count`、`.chip-tell` 會另外驗
   邊框與填色，門檻 3:1（WCAG 1.4.11），兩者有一個達標即可。

CI 在 `.github/workflows/quality.yml`。**刻意不擋部署**——出遊當天早上不該因為一個像素差就上不了線，但違規會在 commit 上留下紅叉。

## 7.5 自動測不到的，用眼睛驗

送出改動前走一遍。這些是機器驗不了但現場會出事的：

- [ ] 把手機亮度調到最低，在窗邊看得清楚嗎？
- [ ] 單手拿手機，拇指構得到主要動作嗎？
- [ ] 快速連點同一列五下，計數對嗎？畫面有跳嗎？
- [ ] 開飛航模式，點名還能用嗎？同步指示有變嗎？
- [ ] 名單捲到第 40 個人，還看得到未到人數嗎？
- [ ] 切成英文，有沒有哪個按鈕破版？
- [ ] 用鍵盤走一遍，焦點順序合理嗎？看得見焦點框嗎？
- [ ] 貼一份 200 人的名單，捲動順嗎？
- [ ] 列印預覽，印出來的是可以用筆勾的空白名單嗎？
