# 元件 · 輸入

### 輸入框 `.input` / 多行 `.textarea`

**用途** — 收使用者輸入的文字。

**解剖** — `.field` 包住 `.label` ＋ 控制項 ＋ 選填 `.hint`。

**規則**

- **字級一律 `--fs-4`（17px）。** iOS Safari 對小於 16px 的輸入框會自動放大頁面。
- 焦點：邊框換 `--accent`，外加 3px `--accent-soft` 光暈，並移除預設 outline。
- `.textarea` 最小高 200px、可垂直調整、行高 1.7（貼上的名單要好讀）。

**內容規則** — `.label` 是名詞短語。`.hint` 說明**格式或後果**，不重複標籤。placeholder 不得取代 label。
**能示範就不要描述**：把接受的格式一條一條寫進 placeholder，等於要人先讀完四行字才敢動手；有辦法給一顆按鈕直接填入範例時，說明就只留一句話（見下方「名單解析預覽」）。

**無障礙契約** — 每個控制項要有關聯的 `<label for>`，或 `aria-label`。錯誤訊息用 `.note-warn` 放在控制項下方。

**實作** — `src/styles.css`

### 搜尋 `.search-wrap`

**用途** — 在長名單裡找人。

**規則**

- `type="search"`，同時比對**姓名、備註與電話**。備註也要比對——號碼已經不是
  解析出來的欄位，而是原文躺在備註裡（見下方「名單解析預覽」）。
- 有內容時右側出現清除鍵（48 × 48）。
- 搜尋**不改變篩選**，兩者是獨立的維度。
- 即時過濾，不需要按 Enter。
- **一直顯示在頂欄裡，不是點了才展開。** 整場反覆在用的東西，多一次「先點開
  才能打字」的步驟是白費的；2026-09 之前曾經做成點右下角浮動鍵才展開，拿掉
  的原因見 04-components/actions.md「點名畫面為什麼不用它：`.dock`」。
  **不自動聚焦**：一進房間就跳出虛擬鍵盤會蓋掉半個畫面，而且不像「按一下
  才展開」那樣是使用者剛做出的明確動作，沒有理由搶走焦點。
- **高度與邊框跟它上下相鄰的控制項對齊，不是借來的通用 `.input` 樣式。**
  48px 高（`--tap-min`），跟正上方的 `.icon-btn`、正下方的 `.segment` 同一個
  高度；填色底＋透明邊框用 `--surface-2`，跟正下方 `.segmented` 的凹槽同一個
  顏色——不然它會看起來像插進控制群組裡的表單欄位，而不是控制群組本身的
  一部分。
- **`.search-clear` 的 `top`／`right` 要換算成 `.input` 的邊緣，不是
  `.search-wrap` 的邊緣。** 兩者曾經是同一件事：`.search-wrap` 左右內距被
  簡寫蓋成 0 的時候，`.input`（`width: 100%`）跟清除鍵的絕對定位剛好都量到
  同一個邊。拆開之後（見上面「搜尋列在頂欄裡」的內距說明）`.input` 縮進了
  `.shell` 的內距（`--sp-4`），清除鍵卻沒有跟著換算，垂直偏了 4px（`top: 50%`
  把 `.search-wrap` 的 `padding-bottom` 也算進去）、右邊也超出 `.input`
  邊界 12px。`right` 要加回 `--sp-4` 才是量到 `.input` 的邊緣，`top: 0`
  （兩者同高、`.search-wrap` 沒有上內距）比再算一次 `50%` 更直接。

**無障礙契約** — 有 `aria-label`（因為沒有可見 label）。清除鍵有自己的 `aria-label`。

**實作** — `src/styles.css`（`.search-wrap .input`）、`src/ui/Room.tsx`

### 代碼輸入 `.code-input`

**用途** — 手動輸入 6 碼代碼加入空間。

**解剖** — 等寬、`--fs-6`、字距 `.34em`、置中。

**規則**

- 輸入時即時正規化：去空白與分隔符、轉大寫、全形轉半形。
- **不做字元替換。** 代碼的字母表刻意排除 `0 O 1 I L`，所以使用者打出這些字元一定是打錯——要明確告訴他，不能猜。
- 字距會讓文字視覺偏左，所以左內距要比右內距大（`--sp-5` vs `--sp-2`）。

**內容規則** — 錯誤訊息要具體：「代碼不會用到 O、0 這些字元，請再確認一次。」

**實作** — `src/ui/Home.tsx`、`src/lib/code.ts`

### 名單解析預覽 `.preview`

**用途** — 在載入名單**之前**，把解析結果攤開給人確認。

**為什麼存在** — 解析器再寬容也會猜錯（例如把「秋季旅遊報名」這種標題當成人名）。
與其猜得更聰明，不如讓主揪一眼看到、直接改掉。**這是刻意的設計選擇，不是解析器不夠好的補丁。**

**解剖** — 每列：序號（`--fs-1` 等寬）＋ 姓名 ＋ 備註 chip ＋ 移除鍵（`.preview-remove`，48px）。

**規則**

- 最高 260px 後內部捲動。同名時另外顯示警告（不自動去重——同名的人是真實
  存在的）。被略過的行數要回報。
- **每一列都要能拿掉。** 只給看不給改，等於把力氣花反了：預覽把正確資訊攤開，
  卻要使用者自己回到 textarea 裡找出是哪一行。猜錯的那幾列會一路留到現場與
  紙本，變成永遠不會被打勾的幽靈成員，於是「還有 N 位沒到」永遠歸不了零。
- **移除是去改那段文字，不是在解析結果上動手腳**（`removeParsedMember()`）。
  文字仍然是唯一的真相，改完重新解析，其他人的位置自然跟著更新。
  一行可能因為行內編號（「1.王小明 2.李美花」）產生多位成員，所以來源要記到
  part 這一層；切點在正規化後的行上算，再拿同一組索引去切原字串
  （`normalizeWidth` 是一對一的字元替換，位置不會跑掉）。
- **不做啟發式標記。** 不去猜哪幾列「看起來像標題」然後幫使用者圈出來——
  那只是把同一個猜測搬到另一個地方，而且猜錯時更難反駁。
- **名字到第一個「空白＋數字」為止，後面整段原文進備註。** 解析器不判斷那串
  數字是什麼：電話、匯款帳號、身分證、座位號一律照抄。舊版會在一行裡到處找
  「看起來像台灣電話」的片段，於是「匯款 700-1234567」被抽成 `001234567`、
  名字變成「李美花 匯款 7」——撥出去是空號，而畫面上沒有一個字說得出為什麼。
  **猜錯的代價不對稱**：漏抓只是號碼留在備註裡（看得見、還撥得到），亂抓卻是
  存下一支看不見的假號碼。
- **攜伴也不再從文字裡認。** `+1`、`帶2人` 跟號碼一樣留在原文裡（`+1` 落進備註，
  `帶2人` 沒有數字開頭的段落所以留在名字裡）。`companions` 欄位只剩舊名單有值，
  於是人頭數與列數在新名單上永遠相等——這個取捨要知道：車門口的「還有 N 位沒到」
  數的是列數，帶來的人得自己看備註。
- 切點在**空白**而不是第一個數字，是為了英文名字：「Alice Chen 0912345678」
  要切在號碼前面，不是切在 `Chen` 前面（中文名字沒有空格，英文有）。因此
  「陳大同 A123456789」不會被切，而「王小明 素食」也不會——沒有數字就沒有切點，
  那一段仍然留在名字裡。
- **撥號改在顯示層回答**（`dialableFrom`）：成員面板把備註裡「0 或 `+` 開頭、
  8～15 碼」的段落做成撥號鍵。顯示層猜錯是可逆、可見的——多一顆鍵，備註原文
  一個字都沒動；資料層猜錯是看不見的。國際號碼因此順便撥得到（`+65 9123 4567`
  原文照抄，`tel:` 自己認得），解析器一種格式都不用支援。

**實作** — `src/ui/RosterInput.tsx`、`src/lib/parse.ts`（`NAME_TAIL`、`dialableFrom`）

### 範例鍵 `.btn` `.btn-sm`

**用途** — 讓第一次開空間的人按一下就看到一個完整的空間長什麼樣：活動名稱一格、
名單一份、解析結果攤在下面。

**解剖** — 表單最上面那一列（`.row`：`.label` ＋ `.spacer` ＋ 按鈕），與
「這場活動叫什麼？」共用一列。**不掛在單一欄位的標籤上**——它填的是整張表，
放在名單那一欄會讓人以為只填名單。

**規則**

- 同一個位置兩個狀態：名單還空著是「填入範例」，範例原封不動是「清除範例」，
  使用者一動手改就兩顆都不給——那時候框裡的是他自己的東西。
- **兩個方向都不碰使用者自己打的字。** 填的時候只填空的那格（先打了活動名稱
  再想看範例的人很常見，那個名字不該被蓋掉）；清的時候只清還跟範例逐字相同的
  那格（`isExampleName` / `isExampleRoster`，兩格分開判）。
- 判準是**逐字相同**，不是「現在有沒有字」。差這一格，這顆按鈕會從「取消範例」
  悄悄變成「清空我剛貼好的 200 人名單」，而畫面上長得一模一樣。所以也不需要
  用確認對話框，去補救一個本來就不該給的動作。
- **範例的每一行都要解析得出一個人**（`src/lib/parse.test.ts` 會驗）。所以範例
  裡不放分組標題行：那種標題會被靜靜吃掉，預覽也不顯示分組，貼進去等於有兩行
  憑空消失——示範一件看不到的事，只會讓人以為那兩行不被接受。
- 說明因此收得很短：placeholder 只留一句，格式細節由範例自己示範。

**內容規則** — 動詞開頭（`填入範例` / `清除範例`），英文一行以內收尾
（`Fill in an example` / `Clear the example`）。

**實作** — `src/ui/NewRoom.tsx`（`fillExample`、`clearExample`）、`src/lib/i18n.ts`（`isExampleRoster`）
