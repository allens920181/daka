## 規格模板

每個元件都用同一套欄位描述。新增元件時照抄這個結構。

```
### 元件名 `.class`

**用途** — 一句話。

**不要用在** — 最容易被誤用的場景。

**解剖** — 有名字的組成部位。

**變體 / 尺寸** — 有哪些，各自什麼時候用。

**狀態** — 預設 / hover / 按下 / 焦點 / 停用 / 載入 / 錯誤，缺哪個要說明為什麼。

**內容規則** — 字數上限、超長怎麼處理、空值怎麼辦。

**無障礙契約** — role、aria、鍵盤行為、焦點。

**實作** — 檔案位置。
```

> **不要用在**這一欄比其他欄位都重要。多數設計系統壞掉不是因為缺元件，
> 是因為某個元件被拿去做它不該做的事。

## 表面與形狀：兩條軸（2026-09 形狀重整）

**這一節是規範，不是建議。** 完整推導見
[設計評估報告 · 2026-09 形狀](../../design-review-2026-09-shape.md)。
它補的是一個一直空著的洞：
[2026-09 整體性評估](../../design-review-2026-09.md) §1.2 找到「每一塊東西都是同一種盒子」，
並寫下「**沒有一條規則說什麼東西該有框、什麼東西不該有**」——然後就沒有人寫那條規則。
於是接下來每一次新增元件都只能照抄旁邊那一個，`--r-2` 一路長到全站 38 條形狀規則裡的 20 條，
而按鈕、名單列、錯誤訊息、QR 卡片、Toast 變成同一個形狀。

規則分成兩條**互不干涉**的軸。**表面說「這是什麼種類」，圓角說「這東西多大、包在誰裡面」。**
把語意塞進圓角、或把尺寸塞進表面，就是上面那種混亂的來源。

### 軸一 · 表面 ＝ 種類

照順序問，第一個答「是」的就是它的類型。**一個元件只能屬於一種。**

| 它是⋯ | 簽名 | 誰 |
| --- | --- | --- |
| **控制項**——你直接操作它 | `--surface` ＋ `--rule-strong`，**不浮** | `.btn` `.input` `.textarea` `.code-row` `.group-chip` |
| **可按的內容塊**——整塊按進去 | `--surface` ＋ `--rule` ＋ `--el-1`，**浮起** | `.recent-item`、`.member`（未到） |
| **靜態內容塊**——只能讀 | `--surface` ＋ `--rule`，**平的** | `.preview` `.copy-row` `.qr-card` `.result-card` `.skeleton-row` |
| **凹槽**——裝別的東西 | `--surface-2`，**不描邊、不浮** | `.segmented` `.note` `.result-preview` `.scan-frame` `.search-wrap .input` |
| **覆蓋層**——浮在遮罩上 | `--surface` ＋ `--el-3` | `.sheet` `.dialog` `.toast` |
| **嵌在上面某一塊裡的觸控區** | **透明**，只有 hover／active 才有底 | `.icon-btn` `.menu-item` `.select-row` `.member-main` `.recent-main` `.segment` |

**一句話記法：陰影的意思是「這一整塊可以按」。**

這不是新發明的，是名單列本來就在教的事——未到的列浮起來（還要你動手）、已到的沉回頁面
（不用了）。2026-09 把它做進 `.member` 的時候沒有推廣出去，於是同一個機制在一個元件上
成立、在其他二十個元件上是隨機的。現在它是全站規則：

- **控制項不浮。** 按鈕與輸入框靠 `--rule-strong`（3:1）定義形狀，那條邊就是它們的全部。
- **只能讀的東西不浮。** 結果紀錄、QR、代碼、預覽都是平的。
- **凹槽不描邊。** 填色已經定義形狀了，再描一條只是把同一件事說第二次。

### 軸二 · 圓角 ＝ 尺寸與巢狀，不是語意

| Token | 用在 | 判準 |
| --- | --- | --- |
| `--r-full` | 藥丸、圓點、握把 | **高度就是它的直徑** |
| `--r-3` 18px | **只有覆蓋層** | 面板與對話框。它不是「比較大的卡片」 |
| `--r-2` 12px | 頁面流裡的一切 | 按鈕、輸入框、列、內容塊、凹槽、Toast |
| `--r-1` 8px | **嵌在別的元件裡的東西** | **內圓角 ＝ 外圓角 − 內距**。分段控制：12 − 4 = 8 |
| `50%` | 真正的圓 | 勾選圈、同步圓點 |

**唯一一個圓角帶語意的地方是藥丸**：「屬於哪一群」一律是藥丸（`.group-chip`、`.role-badge`、
`.chip-tell`），方角留給資料（`.chip`、`.chip-data`）。它成立是因為藥丸的形狀來自**高度**，
不是來自重要性——所以它沒有違反這條軸。

**`--r-2` 是預設值，因此它不表示任何事。** 想靠圓角說「這比較重要」「這是另一種東西」，
答案永遠是錯的：要說種類就換表面（軸一），要說層級就換位置、字級或顏色。

### 三個最常見的誤用

| 誤用 | 為什麼錯 | 怎麼做 |
| --- | --- | --- |
| 給一塊只能讀的東西加 `--el-1`「讓它明顯一點」 | 陰影已經被指派了意思：整塊可以按 | 要明顯就換字級或間距 |
| 用 `--r-3` 表示「這是一張比較大的卡片」 | `--r-3` 是覆蓋層的形狀。頁面裡出現覆蓋層的圓角，會讀成面板裡又疊了一張面板 | 用 `--r-2` |
| 凹槽再描一條 `--rule` | 填色與邊框在說同一件事，兩個一起用就是噪點 | 凹槽只有底色 |

### 這四條有測試在擋

`src/styles.test.ts`：`--r-3` 只准出現在覆蓋層、`--el-1` 只准出現在可按的內容塊、
凹槽不得同時有底色與邊框、`:focus-visible` 不得設 `border-radius`
（設在那裡的圓角會改掉**元件自己**的形狀，見下面的通則 6）。

---

## 通則

1. 元件不得自帶外部邊距。間距由父層的 `.stack` / `.row` 用 `gap` 決定。
2. 元件不得寫死顏色、字級、間距，一律用 token。
3. 每個可互動元件都要有無障礙名稱。
4. 有 hover 態的一定要有 `:focus-visible` 態。
5. 新增變體之前先問：這是新變體，還是既有元件用錯地方了？
6. **元件的形狀不得隨狀態改變。** `:focus-visible` 之類的狀態選擇器不得設
   `border-radius`——那不是在畫框線的圓角，是在改元件自己的圓角。對焦框
   （`outline`）本來就會跟著元件自己的圓角走，所以沒有自己圓角的可按元件要**補上
   圓角**，而不是讓對焦狀態去發明一個。
7. **變體不得把它繼承來的東西整組退掉。** 一個類型的兩個變體如果一個是卡片、
   一個是沒有底也沒有內距的段落，那它就不是一個類型，只是兩個東西共用了一個名字
   （`.banner` 2026-09 就是這樣拆掉的）。
8. **不要為了語意而重複宣告一模一樣的樣式。** `.chip-count` 與 `.chip-note` 曾經
   各自把 `.chip` 已經給過的底色與文字色再寫一次，於是 CSS 看起來有四種晶片、
   實際上只有兩種長相。名字是給 markup 讀語意用的，不是給它長得不一樣用的。
