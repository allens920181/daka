# 元件 · 表面

### 頂欄 `.topbar`

**用途** — 我在哪個 app、我的身分、空間身分、同步狀態、以及一個全域動作。

**解剖**（空間畫面，2026-09 起三列）

```
.room-chrome                 （＝ .topbar，整條 sticky）
├─ .room-chrome-fold         ← 往下滑收起來的那兩列
│   ├─ .app-bar-band     --chrome 底色，滿版（裡面才是 .shell .app-bar）
│   │   └─ .app-bar          標誌 ＋ RollRoom ＋ 設定（與首頁同一個元件）
│   └─ .topbar-inner     ← 空間面板的上緣（圓角 ＋ 會轉彎的髮絲線）
│                          （min-height 48：等於它最高的內容）
│       ├─ 返回（icon-btn 48）
│       ├─ .topbar-title
│       │   └─ .topbar-heading  .role-badge 身分 ＋ .topbar-name 空間名（單行截斷）
│       │                       ＋（關閉時）.topbar-count ＋ .sync 同步圓點
│       └─ 更多（icon-btn 48）
└─ .filterbar                ← 永遠不收
```

**規則**

- `position: sticky`、`--z-sticky`、上方留 `env(safe-area-inset-top)`。
- **底是半透明材質，不是實色**（2026-09，[iOS 評估](../../design-review-2026-09-ios.md) §2.1）：`color-mix(in srgb, var(--paper) 72%, transparent)` ＋ `backdrop-filter: saturate(180%) blur(20px)`。底部動作列同一份。**這不只是好看：它讓人知道底下還有東西、而且正在動**——一條實色的橫槓會把畫面切成互不相干的兩塊，捲動時上面那塊像釘在別的圖層上。
  - **兩層退路，順序不能反。** `@supports not ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px)))` 在後面，`@media (prefers-reduced-transparency: reduce)` 再後面（使用者明講過不要，它得蓋得過前一條）。兩條退路都回到 `--paper` 實色，也就是改動前的樣子。**`@supports` 必須兩個寫法一起測**：Safari 18 之前只認 `-webkit-` 前綴的那個。
  - 按鈕不受影響（`.btn` 自己有 `--surface` 實底），所以動作列上透出來的是按鈕**之間**的縫。頂欄標題沒有底，它確實直接坐在材質上——iOS 的 nav bar 標題也是這樣。
- 副標平常顯示**代碼**；空間關閉時換成「已關閉」（`.topbar-count`）——關閉是全域狀態，不能只靠一條會捲走的橫幅。
- **身分（主揪／協助者）排在空間名前面**，是一顆 `.role-badge` 圖示（2026-09：先從「更多」面板的身分列搬到副標行，再換成圖示、往上挪到名字前面）。「我能不能改」決定這個畫面上哪些事做得動（編輯名單、結束點名只有主揪能做），那是進空間第一眼就該知道的事，不該要先點開「更多」面板。
- **副標那一行（代碼 ＋ 同步狀態）2026-09 整條拿掉了**，這一列因此只剩一行 24px 的標題，`min-height` 也從 `--tap-lg`（56）降到 `--tap-min`（48）——頂欄 121px → 113px。
  **但要說清楚：拿掉那一行本身不省任何高度**（兩行疊起來也只有 46px，撐著這一列的一直是那兩顆 48px 的圖示鍵）。省下的 8px 是拿掉之後才敢把 56 的地板降到 48。**這一列已經到底了：它等於它最高的內容。**
  - **代碼**去「更多 › 邀請點名 › 代碼」——那一頁整頁就是它，字級大到隔著一支手臂唸得出來，而副標行只印得下 11px 的小字。首頁每一列也印著代碼。代價是在空間裡要唸代碼得多按兩下。
  - **同步狀態**縮成名字後面一顆 `.sync` 圓點：這個指示整場都在，但它整場都不該被讀——要傳達的是「顏色變了」，而「已同步」三個字在 99% 的時間裡只是重複一件沒有變化的事。完整說法留在 `aria-label`／`title`。**例外是待上傳筆數**（`.sync-n`）：那是一個會變的數字，變大就代表有東西還沒送出去，所以它印在圓點旁邊。
- **篩選與搜尋住在頂欄裡的同一列**（`.filterbar`，2026-09 併成一列），所以跟著黏住。未到人數就在篩選那排（「未到 N」），不需要另一套「捲出畫面時接手」的機關。搜尋是那一列右邊的放大鏡，點了才往左長出輸入框。
- **標題可點，點了回到名單頂端**（`aria-label` 用 `backToTop`）。200 人的名單捲到底之後，要回到頂端的控制項得往上滑 17 個螢幕，而 `overscroll-behavior-y: none` 連「用力甩」都擋掉了。這是行動裝置的既有慣例，不必再教。
- **頂欄只留一顆圖示動作：「更多」。** 邀請點名 2026-09 在這裡當過一陣子圖示鍵，同月收回「更多」的第一列——**一個空間只該有一顆「更多」**：分享單獨掛在頂欄時，這個畫面上同時有兩個入口通往同一張面板的不同頁，而使用者要記的變成「哪一件事在外面、哪一件事在裡面」。收回來之後頂欄只剩返回、標題、更多，那份選單也不再是薄薄一兩列。代價是發代碼多開一層——那是一場活動按一次、而且不趕時間的動作；真正趕的那一顆（結束點名）在底部動作列上，沒有跟著收進來。
- **編輯模式下頂欄只剩返回、標題輸入框、打勾**：更多不印，那時候畫面上只該剩名單。

**導航列與空間標題列靠「結構」分開，不是靠一條線**（2026-09）。兩者本來都直接
坐在 `--paper` 上，於是「RollRoom」與「← 秋季旅遊 · 出發 ⋮」讀起來是同一坨東西
——而它們是兩件事：一個是 app，一個是你現在打開的那一間空間。

加一條髮絲線不夠：篩選列底下本來就有一條，再加只是變成「一堆髮絲線裡的又一條」，
而兩條平行的淡線反而更像同一塊東西被隨手切開。所以改成講結構：

- **導航列有自己的底色**（`--chrome`，`.app-bar-band`）。底色帶要滿版，所以它自己
  是外層、`.shell` 收在裡面——掛在 `.shell` 裡面的話底色會被左右內距切掉兩道縫。
- **空間是它底下的一塊面板**，面板的上緣就是分界（`.room-chrome .topbar-inner`
  的圓角 ＋ `box-shadow: 0 -1px 0 var(--rule)`）。
- **那道上緣是一條會轉彎的髮絲線，不是填色的圓角。** 面板用的就是頂欄那塊半透明
  材質，不另外上底色——多鋪一層底就等於把「看得到底下的東西在動」關掉，而那正是
  這條頂欄存在的樣子。
- **上緣只能用 margin 跟底色帶拉開，不能加上內距。**「這一列等於它最高的內容」
  （48px 的圖示鍵）是這一列自己的規則，多 4px 的 `padding-top` 就把它撐成 52。
- **`--chrome` 是自己的 token，值目前跟 `--surface-2` 一樣。** 名字不一樣是刻意的：
  `--surface-2` 在這套語言裡的意思是「凹槽 ＝ 你打字的東西」，拿它當導航列的底色
  會讓那個詞多一個意思，下一個人讀到「導航列是凹槽」只會困惑。
- **首頁沒有面板**，只有那塊底色帶：首頁本身就是 app 的頁，底下沒有巢狀的東西。
  帶子底下因此留一格縫（`--sp-3`），空間裡則貼著（縫由面板的上緣負責）。

**app 抬頭跟著進空間**（2026-09）。空間以前是一整頁蓋掉首頁，於是走進去之後畫面上
沒有一個東西說得出「我還在同一個 app 裡」——只剩一個空間名字和一顆返回鍵。現在
`.app-bar`（標誌 ＋ RollRoom ＋ 設定）跟首頁用同一個元件，空間變成這個 app 裡的
一頁，而不是另一個地方。

兩顆出口各在各的列，因為它們**不是同一種東西**：`⚙` 在 app 那一列，它改的是 app
的設定；`←` 在空間那一列，它退出的是這一間空間。

**往下滑收起來，往上滑一點就回來**（`.room-chrome.is-folded`）。三列疊起來 188px，
而 390×844 的螢幕上那是四分之一——**四分之一的畫面在講「你在哪裡」，而使用者是來
看「還有誰沒到」的**。

- **收的是上面兩列，`.filterbar` 永遠不收。**「未到 N」是畫面上唯一回答「還有幾個
  沒到」的東西，搜尋是有人在車門口報上名字時要用的。那兩件事跟著捲走，就得先捲回
  17 個螢幕。
- **往上滑一點就回來，不必捲到最頂。** 200 人的名單捲到底時，「拿回返回鍵」不該要
  人再捲 200 列。方向判斷有 8px 的門檻，而且**沒過門檻就不更新基準點**——每一次
  scroll 事件都更新的話，手指慢慢移動時每次位移都是 1～2px，方向會被雜訊決定，
  頂欄就在原地抖。
- **位移用 `transform`，不是把那兩列的高度收成 0。** 高度收掉的話，這條頂欄在流程裡
  佔的位置跟著變短，**底下整份名單會往上跳一百多 px**——而使用者只是在捲動。
  `transform` 不動版面，也走得到合成執行緒。
- **收起來時那兩列 `visibility: hidden`**：一顆看不見但按得到的返回鍵，比沒有返回鍵
  更難解釋。
- **位移量要量出來**（`ResizeObserver` ＋ callback ref），不能寫死：字級設定、轉向、
  空間名換行都會改變那兩列的高度。**callback ref 不是 `useRef` ＋ mount 時量一次**
  ——這個畫面在載入完成前回傳的是骨架，掛載那一刻頂欄還不存在，量到的是 0，於是
  位移永遠是 `translateY(-0px)`：class 換了、`visibility` 換了，就是不會動。

**代價：「點頂欄回到頂端」要先往上撥一下。** 空間名那一列正好是收起來的其中一列，
而它在「你捲得很深」的時候不在畫面上——那正是想回頂端的時刻。往上撥一下頂欄就回來
（不必捲到頂），接著點它。手勢跟 iOS 點狀態列回頂是同一個方向，多的是那一撥。

**實作** — `src/ui/Room.tsx`、`src/ui/AppBar.tsx`

### 首頁的空間列 `.recent-item`

**用途** — 首頁清單的一列：一個去過或自己開的空間。

**不要用在** — 點名名單（那是 `.member`）。

**規則**

- **框圈住整列，「更多」在框裡面**（2026-09）。它本來是「一顆有框的按鈕 ＋ 框外面
  一顆更多」，於是那顆更多浮在右邊像是不屬於任何一列——七列並排時，它是上面那一
  列的還是下面那一列的，要靠對齊去猜。
- **外層是 `div`，裡面兩顆各自是 `button`**（`.recent-main` ＋ 那顆 `.icon-btn`）：
  巢狀按鈕是無效的 HTML。好處是可點範圍也跟著誠實了——框裡除了那顆更多，其餘
  都會進到空間。
- **內距掛在 `.recent-main` 上，不在外框上**：掛在外框上會讓那顆 48px 的圖示鍵
  縮水，而它是整列上最小的觸控目標。
- **兩顆之間不畫界線**（2026-09）。那條貫穿整列高度的 1px 讓這一列讀起來像一格
  表格，而首頁上七列並排時就是七條短豎線在那裡列隊。兩個目標之間本來就有內距與
  各自的 hover 底色說得出「這是兩個東西」。那顆圖示鍵的右側圓角要跟著外框收，
  不然 hover 的底色會從框的圓角裡溢出一個直角。
- **那顆「更多」的 `aria-label` 要帶空間名字**（「更多：<空間名>」）：一屏上有七顆
  一模一樣的「更多」，只唸得出「更多」的話完全聽不出按下去的是哪一個空間。
  它打開的是空間本身的事（建立副本、刪除空間），見 04-components/overlays.md。

**實作** — `src/ui/Home.tsx`、`src/styles.css`

### 代碼大字 `.code-display`

**用途** — 在「更多 › 邀請點名 › 代碼」那一頁把代碼顯示到隔著一支手臂也唸得出來。

> **邀請點名是「更多」的第一列**（2026-09：從頂欄那顆圖示鍵收回來，並從「分享」
> 改名——「分享」那兩個字在手機上專指「叫出系統分享單」。首頁每一列右邊那顆
> 「更多」是另一份選單，裝的是空間本身的事，見 04-components/overlays.md）。三種方式各自
> 一列、各自一頁，順序是**代碼 → 連結 → 二維碼**：代碼是隔著車門喊得出去的，
> 連結是貼進 LINE 群的，二維碼要對方拿起手機對著你的螢幕——愈往下愈需要兩個
> 人站在一起。一頁只放一種，`.code-display` 才有整頁的寬度可用。
>
> **這一頁 2026-09 只剩那三列。** 拿掉的兩塊：
>
> - 底下那句「把代碼、連結或二維碼給他們，不用註冊、不用安裝」——它在回答一個
>   沒有人在這一刻問的問題（會打開這一頁的人早就決定要發代碼了）。
> - **「現在在這個空間裡」整區**（誰已經進來了）。它回答的是「代碼發出去之後有
>   沒有人真的進來」，是個好問題；但它要一整套 presence 訂閱才答得出來，而那套
>   東西答錯的代價（在別人明明已經進來時說「目前只有你」）比答對的收穫大。
>   **入口跟功能一起走**：`peers`／`presenceReady`／`track()` 一併移除，不留
>   一條每次進空間都跑、卻沒有任何畫面在看的訂閱。
> - **代碼那一列右邊也不再印代碼本身。** 點進去那一頁整頁就是它（`.code-display`
>   要的字級在選單列裡放不下），在列上先印一次小的只是同一個字印兩次。
>   「選單列不寫副說明」那條規則因此少了一個例外。
>
> **單機模式下整頁換掉。** `connection === 'local-only'` 時三種方式一個都不列
> （沒有 `.code-display`、沒有 `.qr-card`、沒有連結按鈕），改成一塊
> `.note-warn`：「這個空間只有你看得到」＋別人會看到什麼。發出去的代碼在這個
> 模式下對任何人都沒有用——五個同工會在車門口看到「找不到這個代碼。請確認有
> 沒有打錯」，然後以為是自己打錯而重試三次。見 01-foundations §1.2 原則 5 的
> 第 1 條。**但「結束點名」那三顆照樣在**（複製結果、下載 CSV、存成 PDF）：把結果
> 貼進 LINE、存一份 CSV 或印一張紙都不需要任何連線，跟著藏掉等於單機使用者連自己
> 點完的名單都帶不走。

**規則** — 等寬、`--fs-7`、字距 `.18em`、置中。字距造成的視覺偏移用左右不等內距補償。

- **複製是那串字右邊的一顆 48px 圖示鍵**（`.copy-row`，2026-09），不是底下一整列
  滿版按鈕。同一件事（把這串字帶走）不該在同一頁上出現兩次——一次是那串字本身，
  一次是一整列寫著「複製代碼」。框畫在 `.copy-row` 上，字與鍵各自不再有自己的框。
  純圖示鍵，所以 `aria-label` 一定要有（「複製代碼」／「複製連結」）。
- **代碼那一頁左邊補一個跟那顆鍵等寬的空白**（`.copy-row.is-centered::before`），
  代碼才落在整個框的正中間，而不是被右邊那顆鍵擠得偏左。連結是靠左的長字串，
  不需要這個補償——所以補償掛在 class 上，不是靠選擇器去猜。
- **連結那一頁底下留下來的是「傳給別人」**（`.btn-primary`，叫出系統分享單）：
  那是另一件事，不是複製的另一種說法。

**內容規則** — 永遠大寫，永遠不加分隔符（`K7F2QM` 不寫成 `K7F-2QM`）——使用者會照著打，多一個符號就多一次打錯。

> **同一手法在另一個地方也用了**：「加入空間」的代碼框與「加入」也是一個框
> （`.code-row`，見 04-components/inputs.md）。差別在邊的強度——這裡是容器
> （`--rule`），那裡整個框是一個可互動元件的邊界（`--rule-strong`）。

**實作** — `src/ui/Sheets.tsx`、`src/styles.css`（`.copy-row`）

### QR 卡片 `.qr-card`

**用途** — 讓協助者掃碼加入。

**規則**

- **一律白底黑碼，即使深色模式。** 掃描器要的是對比。
- 這是全系統唯一允許寫死 `#fff` 的地方，例外寫在 `src/styles.test.ts`。
- 最大寬 240px（更大不會更好掃，只會佔掉面板空間）。
- 產生失敗時安靜降級——代碼與連結仍可用，不顯示錯誤。

**無障礙契約** — `<img>` 的 `alt` 要包含代碼，讓看不到 QR 的人也拿得到資訊。

**實作** — `src/ui/Sheets.tsx`（`QrCard`）

### 結果卡片 `.result-card`

**用途** — 點名結束之後印在名單上方的**定格結果**：「已結束 · 還差 3 位 · 已到 17／20」，右邊跟著「複製」與「CSV」。

**不要用在** — 進行中的狀態。點名還在跑的時候，那個數字住在篩選列（`.segment .count-pending`）。

**規則**

- **它是靜態內容塊：`--surface` ＋ `--rule`，不浮。** 陰影在這個系統裡的意思是
  「整塊可以按」（見 [README · 表面與形狀](README.md)），而這一塊是紀錄，只能讀。
- **不是警告。** 它 2026-09 之前掛的是 `.banner-warn`——把整場點名的**最終答案**
  印在警告色上，等於「你把事情做完了，然後畫面對你亮橙燈」。不管數字是「全到齊」
  還是「還差 3 位」，那都是這一場的事實。

### 身分圖示 `.role-badge`

**用途** — 「我在這個空間是誰」：主揪或協助者。出現在首頁每一列與空間頂欄，
各一次。

**不要用在** — 名單成員的附加資訊（那是 chip）。這是身分，chip 是屬性。

**解剖** — 24px 的圓底 ＋ 16px 的圖示。**主揪＝鑰匙**（這支手機握著改動這個空間
的權限，畫面上哪些事做得動就是由它決定的）、**協助者＝人**。

**變體** — `.role-badge`（中性底）、`.role-badge.is-owner`（`--accent-soft` 底、
`--accent` 圖示）。

**規則**

- **排在標題前面**（2026-09）。它講的是「我」，比它後面那個名字更早被讀到；而
  它原本那兩個位置（首頁那一列的最右邊、頂欄副標行的第一格）分別要讓給「更多」
  與空間名字。
- **形狀要分得開，顏色只是加強。** 色盲、以及最低亮度下的螢幕都分不出顏色，
  但形狀還在。
- **不可點擊。** 要可點就不是身分標記了。
- **一定要有 `aria-label`（以及 `title`）**，值就是「主揪」／「協助者」，
  容器是 `role="img"`。這是它 2026-09 從一顆寫著字的藥丸換成圖示之後唯一還
  說得出意思的地方——**代價是手機上沒有 hover，第一次用的人只能靠形狀與顏色
  分辨**。換到的是首頁一列多出約 60px 給空間名字、頂欄少一格。
- **編輯模式下不印**（頂欄那一顆）：那時候畫面上只該剩名單。
