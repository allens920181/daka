# RollRoom · 設計系統

這是**規範**，不是建議。能自動檢查的規則都有對應的測試；不能自動檢查的，寫成可以用眼睛驗收的句子。

改動 UI 時的優先順序：**使用者說的話 > 這份規範 > 個人品味**。
覺得某條規則擋路，就改規範並寫下理由，不要繞過它。

## 三十秒版本

- 畫面上最大的數字永遠是「還有幾位沒到」。
- 任何操作都在 100ms 內從本地狀態給出結果，不等網路。
- 每次狀態變更都有 5 秒的無條件復原。
- 可互動元素 ≥ 48×48px，名單列 ≥ 64px。
- 文字對比 ≥ 4.5:1（大字 3:1），淺色深色都要過。
- 字級只有八階，間距以 4px 為基準，圖示只有三種尺寸。
- 使用者看得到的字全部在 `src/lib/i18n.ts`，元件裡不得寫死中文。

## 規範是可執行的

| 檢查 | 指令 | 驗什麼 |
| --- | --- | --- |
| Token 靜態檢查 | `npm test` | 原始碼有沒有繞過 token（硬寫色值、字級、z-index、動畫時間） |
| 設計規範執行期檢查 | `npm run audit:design` | 渲染出來的對比、觸控尺寸、字級、無障礙名稱、橫向溢出 |
| 端對端 | `npm run e2e` | 元件的行為契約（焦點、Esc、復原、列印） |

兩種檢查互補，抓到的問題不一樣：硬寫一個剛好合格的顏色，執行期檢查看不出來，但它會在下次改 token 時脫隊。

規範被違反時只有兩個正當結局：**修程式碼，或修規範**。
